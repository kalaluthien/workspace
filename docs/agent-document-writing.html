Options

Two axes, named before any option is judged. Locality: is the file that holds a rule loaded by the actor that must obey it, at the moment the rule binds — or does obeying it require a second read the actor may skip. Enforcement: what makes a violation fail, rather than merely be discouraged.

OptionWhat it doesCostWhat it gives up
README as master Keeps docs/README.md as the constitution and demotes every other site to a pointer. Six sites trimmed; the README grows to absorb what they held. Locality. The writer still needs the rules inside its own definition to act on them, so the README–agent duplication survives as structure rather than accident.
Writer as constitution Makes document-writer.md the one normative description of the whole system, spec rules included. One file serves two audiences, so spec-only prose rides in the writer’s context on every invocation. A clean single audience per file, and a single repository: the definition is versioned in ~/.claude, not beside the documents it governs.
Writer as sole author Routes every document, spec and view alike, through the writer, so its definition is total by construction. Every spec change becomes a delegation; all documentation serializes behind one agent. “A spec is written by the agent doing the work, in the same change as what it governs” (docs/README.md §Writing pipeline), whose whole point is that the doing agent holds the context.

On locality, only Writer as constitution puts the rules in a file the acting agent already loads, whereas a README is read when someone remembers to. On enforcement, none of the three enforces anything by itself, because enforcement is a machine check that all three need equally.

Recommendation

Writer as constitution wins on locality and ties on enforcement, so it ships with a checker alongside it rather than instead of it. The governing principle is one sentence: a rule lives in the single file its actor loads at the moment the rule binds; every other mention is a pointer. The writer is the only actor that touches every view in every entry, and its move to the user level at b6bff78 already put it where a session in any entry loads it.

The recommendation flips on either of two costs. The definition would serve two audiences, so every writer invocation pays for spec-rules prose it never uses — at 86 lines against 181 that is cheap, and if the spec rules grow until the file reads as two documents, they split into a spec-rules file the spec template points at.

Not shown The second cost arrived with b6bff78 and is not weighed anywhere. The constitution would live in ~/.claude while the documents live in the entries, so no single commit can change a rule and the documents it governs together — the property change 1 was written to buy. Whether locality is worth that is unrecorded, and this document does not decide it.

The smallest first step is one commit: rewrite ~/.claude/agents/document-writer.md to hold the rule set, and shrink docs/README.md to the two-kinds table, the contract block and a pointer. The remaining sites keep working as stale copies until the phases below reach them, so nothing else has to move for that commit to leave the system correct.
