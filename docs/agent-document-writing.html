Six files state the document system’s rules, but the copies have already diverged, so the writer agent’s definition should hold the one normative description and every other mention should become a pointer.

One rule set is written out in six files, and two of the copies are already wrong

Every site below carries normative text about how documents are written — not a pointer to it, the rule itself. Changing one rule is therefore a six-file change, and two sites have already drifted far enough to send an author somewhere that does not exist. The owner pays for it twice: as the only reviewer, and as the reader of a catalogue that now misdescribes its own system.

Two further defects follow from the same shape. The parent relation is asserted only by the parent: docs/README.md line 4 claims to be “the parent of every docs/ directory”, while a search of camera/docs/ for workspace/docs, ~/workspace or “parent document” returns nothing — that entry’s 218-line README still describes a nine-template system of its own. And enforcement is split by entry rather than shared: camera/hooks/pre-commit runs a 224-line script/check-docs.py over staged documents at commit time, while the workspace’s only hook is the three-line no-main-commits guard, so nothing machine-checks workspace/docs at all.

The choice is which file holds the rules, and it turns on who reads them and what makes a violation fail

Two axes, named before any option is judged. Locality: is the file that holds a rule loaded by the actor that must obey it, at the moment the rule binds — or does obeying it require a second read the actor may skip. Enforcement: what makes a violation fail, rather than merely be discouraged.

OptionWhat it doesCostWhat it gives up
README as master Keeps docs/README.md as the constitution and demotes every other site to a pointer at it. Five files trimmed; the README grows to absorb what they held. Locality. A prose file enforces nothing, and the writer still needs the rules inside its own definition to act on them — so the README–agent duplication survives as structure, not accident. The reader of the rules and the home of the rules stay two files.
Writer as constitution Makes .claude/agents/document-writer.md the one normative description of the whole system, spec rules included, with every other site a pointer. One file serves two audiences — the writer’s own system prompt and reference for the doing agents that write specs — so spec-only prose rides in the writer’s context on every invocation. A clean single audience per file. The spec rules are read by an agent that is not the file’s owner, through a one-line pointer in the spec template header.
Writer as sole author Routes every document, spec and view alike, through the writer, so its definition is total by construction. Every spec change becomes a delegation; all documentation serializes behind one agent. “A spec is written by the agent doing the work, in the same change as what it governs” (docs/README.md §Writing pipeline). The doing agent holds the context a spec needs, and a handoff through a second agent is lossy exactly where fidelity matters most.

On locality, only the second option puts the rules in a file the acting agent already loads: the writer’s definition is read on every act of view writing, whereas a README is read when someone remembers to. On enforcement, none of the three enforces anything by itself — enforcement is a machine check, and all three options need the same one. That is why the recommendation carries a checker alongside it rather than instead of it. Writer as sole author wins locality outright and is still the weakest option, because it buys locality by moving the author, which is the one thing the pipeline decision fixed.

The writer’s definition is the only file loaded at the moment the rules bind, so the rules belong in it

Writer as constitution wins on locality and ties on enforcement. The governing principle is one sentence: a rule lives in the single file its actor loads at the moment the rule binds; every other mention is a pointer. The writer is the only actor that touches every view in every entry, so its definition is where the source of truth and the point of use become the same file.

Eight concrete changes carry it:

  1. document-writer.md absorbs the normative content of README.md: the two-kinds split, the three view doctypes, naming and catalogue rules, the pipeline, and a new spec-rules section covering the five section shapes (decision, rule, procedure, capability, ledger).
  2. docs/README.md shrinks to the two-kinds table plus one pointer at the agent definition; INDEX.md stays the catalogue.
  3. .claude/CLAUDE.md keeps one routing line — docs work delegates to document-writer — and drops the naming restatement.
  4. Templates demote to skeleton plus machine contract. The contract gains per-shape required-sections, so the capability shape re-imposes Behavior, Configuration and Acceptance — the part of camera’s feature.md that the merge into spec.md silently dropped.
  5. Components demote to pure self-demonstration; their rule prose moves into the agent definition, and the stale report/mockup doctype list in provenance.html goes with it.
  6. figure.html gains the two pieces of camera’s mockup.html worth keeping: a phone-frame demonstration (viewBox="0 0 360 720") and the numbered ships-today/comes-from ledger table for drawn options.
  7. Enforcement unifies: camera’s check-docs.py generalizes into a workspace-level contract checker that any entry’s pre-commit hook calls; the writer keeps its write-time rubric report; and a proposal whose recommendation ships flips Status to Adopted in the shipping commit.
  8. A child entry adopts the system by delegating its view writing to the writer and calling the shared checker — behavioral coupling through one gate, not prose copied into its README.

Change 7 is cheaper than it looks, and change 1’s cost is the thing to watch.

The checker already separates the generic part from the camera part

camera/script/docs_chapters.py derives the chapter model from INDEX.md and each contract from its template’s own comment, and its docstring states the property that makes it portable: “everything here is a calculation over text passed in by the caller … no caller has to teach this module where its bytes came from.” What is camera-specific sits in check-docs.py instead — the camera-roll leak patterns and the Category field — so generalizing means lifting the 5.3 KB calculation module and leaving the entry-specific checks behind it.

The recommendation flips if document-writer.md outgrows its job. It serves two audiences by design, and the spec-rules section is read by doing agents rather than by the writer, so every writer invocation pays for prose it never uses. At today’s sizes — 44 lines of writer definition against 84 lines of README — that cost is small and the locality is worth it. If the spec rules grow to where the file reads as two documents stapled together, split them into a spec-rules file the spec template points at, and the constitution becomes two files that still hold each rule once.

The smallest first step is one commit: rewrite document-writer.md to hold the rule set, and shrink README.md to the two-kinds table and a pointer. Nothing else has to move for that commit to leave the system correct — the remaining sites keep working as stale copies until the phases below reach them, and the phases can then land one at a time.

Why the Status rule Change 7’s last clause has its evidence in this file. The previous revision of docs/agent-document-writing.html recommended adopting the parent system; the system was built at 3e3d22f and minimized at 50aac0f; and at a4d8e2b the document still read Status: Open. Nothing flipped it, because nothing was responsible for flipping it.

Forty-five documents move in four phases, each exiting on a machine check rather than on review

Backward compatibility is not owed — the owner deferred it with the migration itself (2026-08-02, owner decision, docs/README.md) — so a document is rewritten onto the new contract, never shimmed to satisfy both. Each phase exits when the generalized contract checker passes over that entry’s docs/ — a criterion an owner can run, not a judgment a reviewer renders.
