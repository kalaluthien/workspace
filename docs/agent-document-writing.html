Answer

Conclusion
  1. 1Constitution. ~/.claude/agents/document-writer.md holds the whole normative description — the two kinds, the three doctypes, naming, the procedure, the style, the guardrails — in 231 lines, with templates/ and components/ beside it (~/.claude a644f45).
  2. 2Pointers. Four sites kept a pointer and nothing more, and the entries’ eight template copies were deleted (camera cf93d7f, board ce99e34).
  3. 3Enforcement. It landed after the move: all three repositories’ pre-commit hooks run scripts/check-docs (workspace 591864e).
  4. 4What is left. The entries’ fifteen views still wait on a re-render, and the templates still carry 493 lines of rule prose. Both are the owner’s call.

Problem

Conclusion
  1. 1Seven sites. At workspace b969155 the rules sat in docs/README.md, .claude/CLAUDE.md, the agent definition, four templates, five components, and eight entry copies — 934 copied comment lines in the entries alone.
  2. 2A rule reached six. The brevity rule added on 2026-08-04 landed in six files and in none of the eight entry copies (camera 140ac74, board 43358c0), so adding one rule was a seven-site edit that nothing completed.

Options

Conclusion
  1. 1Two axes. Locality — does the actor that must obey a rule load the file holding it, at the moment the rule binds; enforcement — what makes a violation fail rather than merely be discouraged.
  2. 2One axis decided it. Only Writer as constitution puts the rules in a file the acting agent already loads, and enforcement tied at nothing, because it is a machine check all three options need equally.
OptionWhat it doesCostWhat it gives up
README as master Keeps docs/README.md as the constitution and demotes every other site to a pointer. Six sites trimmed; the README grows to absorb what they held. Locality. The writer still needs the rules inside its own definition to act on them, so the README–agent duplication survives as structure rather than accident.
Writer as constitution Makes document-writer.md the one normative description of the whole system, spec rules included. One file serves two audiences, so spec-only prose rides in the writer’s context on every invocation. A clean single audience per file, and a single repository: the definition is versioned in ~/.claude, not beside the documents it governs.
Writer as sole author Routes every document, spec and view alike, through the writer, so its definition is total by construction. Every spec change becomes a delegation; all documentation serializes behind one agent. The rule that a spec is written by the agent doing the work, in the same change as what it governs — that agent is the one holding the context.

Recommendation

Conclusion
  1. 1Writer as constitution. One sentence governs it — a rule lives in the single file its actor loads at the moment the rule binds — and the writer is the only actor that touches every view in every entry.
  2. 2The cost it accepted. The constitution lives in ~/.claude while the documents live in the entries, so no single commit changes a rule and the documents it governs together.
  3. 3The flip. It reverses if that split starts costing more than the locality it bought, or if the file grows until it reads as two documents, at which point the spec rules split into a file the spec template points at.
  • The first step was one commit. Workspace 4ddc0d4 rewrote the definition to hold the rule set and shrank docs/README.md to the two-kinds table, the contract block and a pointer.
  • A spec now records the decision. docs/agent-document-system.md (312746d) carries the choice, both kill reasons, and the deferred work.
