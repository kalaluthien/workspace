Options

Two axes, named before any option is judged. Locality: is the file that holds a rule loaded by the actor that must obey it, at the moment the rule binds — or does obeying it require a second read the actor may skip. Enforcement: what makes a violation fail, rather than merely be discouraged.

OptionWhat it doesCostWhat it gives up
README as master Keeps docs/README.md as the constitution and demotes every other site to a pointer at it. Six sites trimmed; the README grows to absorb what they held. Locality. A prose file enforces nothing, and the writer still needs the rules inside its own definition to act on them — so the README–agent duplication survives as structure, not accident. The reader of the rules and the home of the rules stay two files.
Writer as constitution Makes .claude/agents/document-writer.md the one normative description of the whole system, spec rules included, with every other site a pointer. One file serves two audiences — the writer’s own system prompt and reference for the doing agents that write specs — so spec-only prose rides in the writer’s context on every invocation. A clean single audience per file. The spec rules are read by an agent that is not the file’s owner, through a one-line pointer in the spec template header.
Writer as sole author Routes every document, spec and view alike, through the writer, so its definition is total by construction. Every spec change becomes a delegation; all documentation serializes behind one agent. “A spec is written by the agent doing the work, in the same change as what it governs” (docs/README.md §Writing pipeline). The doing agent holds the context a spec needs, and a handoff through a second agent is lossy exactly where fidelity matters most.

On locality, only the second option puts the rules in a file the acting agent already loads: the writer’s definition is read on every act of view writing, whereas a README is read when someone remembers to. On enforcement, none of the three enforces anything by itself, because enforcement is a machine check and all three options need the same one.

That is why the recommendation carries a checker alongside it rather than instead of it. Writer as sole author wins locality outright and is still the weakest option, because it buys locality by moving the author, which is the one thing the pipeline decision fixed.

Recommendation

Writer as constitution wins on locality and ties on enforcement. The governing principle is one sentence: a rule lives in the single file its actor loads at the moment the rule binds; every other mention is a pointer. The writer is the only actor that touches every view in every entry, so its definition is where the source of truth and the point of use become the same file.

The two checkers own different halves, so unifying is a call site rather than a rewrite

scripts/check-docs states its own boundary: “What is not checked: everything the templates own — required sections, figures, rubric items. A template’s contract is checked where the template is filled (an entry’s own pre-commit).” Camera’s script/docs_chapters.py owns exactly that half, parsing required-fields, required-sections and required-elements out of a template comment, and its docstring names the property that keeps it portable: “Everything here is a calculation over text passed in by the caller … no caller has to teach this module where its bytes came from.” The two do not overlap, so an entry that wants both adds a call rather than merging two scripts.

The recommendation flips if document-writer.md outgrows its job. It serves two audiences by design, and the spec-rules section is read by doing agents rather than by the writer, so every writer invocation pays for prose it never uses. At today’s sizes — 66 lines of writer definition against 168 lines of README — that cost is small and the locality is worth it.

If the spec rules grow to where the file reads as two documents stapled together, split them into a spec-rules file the spec template points at, and the constitution becomes two files that still hold each rule once.

The smallest first step is one commit: rewrite document-writer.md to hold the rule set, and shrink README.md to the two-kinds table, the contract block and a pointer. Nothing else has to move for that commit to leave the system correct — the remaining sites keep working as stale copies until the phases below reach them, and the phases can then land one at a time.

Why the Status rule Change 7’s last clause has its evidence in this file. The revision before last recommended adopting the parent system; the system was built at 3e3d22f, minimized at 50aac0f, and adopted by both entries (camera 140ac74, board 4ee9f83) — and at 6c5ef3d this document still reads Status: Open. Nothing flipped it, because nothing is responsible for flipping it.
