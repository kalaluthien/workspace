Scope of a memtype declaration

  • It does not pick the pool. The memtype fixes the lifecycle alone.
    • Scope picks the pool.
    • setup-herdr sits in the global pool, and setup-sweep-sessions sits in the workspace pool.
    • Both declare procedural.
  • No memtype is barred from a pool. A pool holding no file of some kind reflects that project's work.
    • The absence states no rule about the prefix.
  • A fixed filename is not a memtype signal. pitfalls takes one file per pool and no prefix at all.
    • It declares procedural like the prefixed rows beside it.
  • A decision is not a memtype. The choice and the rule it settled file apart.
    • The choice goes to a history- file when its evidence would otherwise vanish.
    • The chosen rule goes where rules of its kind live.
  • Declaring a memtype does not make a file authoritative. A versioned home outranks a pool file on the same subject.
    • The prefix the pool file carries does not change that rank.

The set of memtypes is open, and it moves by an edit to the table. topic- was added on 2026-08-16. profile- was merged into feedback- on 2026-08-15, after a single file had ever used it. Each change was an owner decision, written into the table in the same commit. ~/.claude/CLAUDE.md:147,155 @ 8a82a8e ~/.claude/projects/-Users-hyungmokim-workspace/memory/history-workspace-refactor.md:204-231
