A memory file's kind — its memtype — is read from one question, what would make this file wrong, and the five answers that question admits are the whole set, so every file in the live pools carries exactly one.

Note The Commit field pins ~/workspace, the tree this view is written in; the schema it renders lives in another repository, ~/.claude at 8c78a4e, and the pools it counts are version-controlled nowhere — that repository's .gitignore ignores /* and tracks zero files under projects/.

Discriminators

The falsifier separates the three classes of the memtype axis, and inside each class that holds a pair it separates again: backlog from profile- by whether the file is about work or about the owner, and setup- from feedback- by what losing the file costs.

MemtypeHoldsWrong when
history-what version control cannot see: changes to unversioned things, and rejected options with their kill reasonsnever — nothing falsifies it, so it only grows
backlogthe pool's live work, one file per poolthe work closes; done is deletion, and no done marker exists
profile-who the owner is: a standing preference that outlives any taskthe owner's preference changes
setup-one tool's or environment's own factsthe tool changes; the fact is re-derivable, so losing it costs one probe
feedback-a rule bought with an observed failurethe practice that bought it is gone; the rule is not re-derivable, so losing it repeats the failure

Pool independence

A memtype fixes a file's lifecycle and never its pool, which is chosen by scope instead — global for a machine-wide fact, workspace for what coordinates several projects, a project pool for what only that project touches. setup- is the case that shows the two axes are independent, carrying thirteen machine-wide facts in the global pool and one file each in the workspace, camera, and notes pools.

Omissions

The figure and tables claim the memtype set, its axis, and its boundaries, and nothing else. Not shown, deliberately:

  • File contents — the tables name what each memtype holds, never what any file says.
  • Pool routes — which pool a fact belongs to is decided by scope, and the sibling view agent-config-scopes.html owns that mapping.
  • Item grammar — the marker, tag, and date form inside a backlog.md belong to the pool contract, not to the memtype that admits the file.
  • Enforcement — no checker named in "Filing" pairs a filename's prefix with its metadata.type; the one hook it names, check-backlog-format.py, compiles the pool contract's item grammar only. The census above is a walk, not a guarantee.
