One report at session end

One new hook writes down what a session still holds when that session ends.

The record covers three things: the session’s git worktree, the board row it claimed, and the panes it spawned. The hook removes none of them and refuses nothing.

Domain

A delegated session is one claude session in a herdr pane, working one repository. Such a session takes 3× claim. The harness offers 2× event that could return them. scripts/launch-session starts one session. Firing points of Stop and SessionEnd

The two events answer different questions. Stop says a turn finished. SessionEnd says the session finished. A teardown wired to the first one runs while the session is still working.

Claims a finished session leaves standing today

The worktree counts balance. The pane counts do not. That gap is the one measured leak, and it names the claim any cleanup must reach first.

Proposed homes for the cleanup

4× option for one job. Only the sweep is built. Every box nobody has written is drawn dashed.

  1. 1

    Sweep on demand — today’s arrangement. Nothing new is wired. sweep-sessions classifies every delegated session and closes only the spent ones. It never closes the calling pane.

    • gives up: timing. The sweep runs when a person asks for it.
    • verdict: standing. Every other option leaves it in place.
  2. 2

    SessionEnd reporter — one hook on SessionEnd that records the ending session’s worktree, ticket claim, and spawned panes. It removes nothing and refuses nothing.

    • gives up: the clearing itself, which still needs a second actor.
    • a report cannot destroy work, so a wrong record costs a reader one line
    • verdict: recommended.
  3. 3

    SessionEnd destructor — the same hook, which also removes the worktree, releases the ticket claim, and closes the spawned panes.

    • gives up: certainty. SIGKILL leaves the hook unfired. That is the case where cleanup matters most.
    • gives up: safety on a worktree, which can hold the only copy of its work
    • needs a named exception to the rule that forbids closing a pane nobody created ~/workspace/.claude/CLAUDE.md:93 @ workspace 5a9a9e8
    • verdict: killed on reach. The measured leak is panes rather than worktrees. The destructive half therefore buys little.
  4. 4

    Cleanup on Stop — any of the three moves above, wired to the turn-end event instead.

    • verdict: killed on the event. Stop fires at every turn end. A teardown there removes a worktree the session is still working in. The 2021 firings over 500 sessions measure that gap.

Two facts pick the reporter. The measured leak is spawned panes, which the destructive half of a session-end hook does not reach any better. A destructor that misses a kill signal cannot be the thing anybody relies on. sweep-sessions therefore stays standing under every option.

⚠️

A destructor sometimes does not run. SIGKILL leaves a SessionEnd hook unfired. A killed session is the one most likely to leave a claim behind.

Two gaps sit under this recommendation, and neither is closed
  • The operator-closed pane. The probe covered a normal exit and SIGTERM. Whether SessionEnd fires when a person closes a herdr pane was not probed.
  • The claim door’s history. The door landed on 2026-08-19, and one day of records exists. The leak rate for a ticket claim is unknown rather than low.

Decisions for the owner

Three questions carry this proposal. Each one takes a yes or a no.

  1. Adopt the SessionEnd reporter at all? A yes adds a fifth declared hook to ~/.claude/settings.json. That hook fires once per session end, in every repository. ~/.claude/settings.json:5-51 @ dotclaude a1fa211
  2. May a session release its own board ticket claim when it ends? A yes lets the hook call the board door for the one row this session claimed. It reaches no other row. It closes nothing.
  3. May the delegating layer close the panes it spawned when the spawning session ends? A yes writes a named exception into rule 3 of “Concurrent agents”, in ~/workspace/AGENTS.md.
