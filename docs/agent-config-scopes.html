Answer

Conclusion
  1. 1 Global. What holds on any repository — the principles, the six filing routes, the skill-authoring rule, the one agent definition — lives in ~/.claude/ and reaches every session on the machine.
  2. 2 Workspace. What coordinates the entries — the entry table, the services rule, the output style, the delegating skill — lives in ~/workspace/.claude/.
  3. 3 Project. How to work inside one entry lives in that entry's own .claude/, and nothing there reaches a sibling.
  4. 4 The rule behind it. A kind files to the scope whose reach matches how far its claim holds, and the router that assigns it never sits below a destination it chooses between.

Reach

Conclusion
  1. 1 Composition. A session composes the three scopes rather than choosing between them, and the working directory selects exactly half of what it loads.
  2. 2 Dormancy. A rule from any scope waits until the session reads a file its paths key matches — never when it writes one — so a rule is the only kind whose arrival depends on what the session opens.
  3. 3 Snapshot. Subagents inherit the whole composition, snapshotted at session start; skills hot-reload mid-session, a new agent definition registers only on restart.

Routing

Conclusion
  1. 1 No self-placement. Every scope declares its predicate in the opening lines of its CLAUDE.md and a router elsewhere assigns it, so no file decides its own home.
  2. 2 Router position. A router sits at the outermost scope of its candidate set and never below one of them — "Filing" sits at the global scope and routes into all three — which lets a reader who knows what a thing is find where it goes without opening any candidate.

Omissions

The figure and tables claim placement, reach, and routing, and nothing else. Not shown, deliberately:

  • Two trees — the Commit field pins ~/workspace; the configuration this view describes lives in a second repository, ~/.claude at 1fe7e9d, and the memory pools under it are version-controlled nowhere.
  • File contents — the tables name files and the kinds they hold, never what a file says.
  • Settings, hooks, and plugins — settings.json at both upper scopes and in two entries, the one authored hook check-backlog-format.py, and the skills supplied by ~/.claude/plugins/ are harness machinery over the kinds rather than authored configuration of a kind.
  • Non-pool directories — ~/.claude/projects/ holds 14 directories and only 6 carry a memory/ pool; camera/.claude/worktrees/ and ~/workspace/.claude-worktrees/ are both empty here.
  • Load mechanics — the reach table names what selects each source, not the order, the token budget, or what happens when two scopes disagree.
  • History — which scopes and entries existed before today; that log is the workspace pool's history-workspace-refactor.
