Each configuration kind files to the scope whose reach matches how far its claim holds, and every router that makes such a choice sits one scope above the destinations it chooses between.

Elements

ElementTypeDescription
Global — ~/.claude/configuration directorythe outermost scope, whose claims are meant to hold in any repository on the machine
Workspace — ~/workspace/.claude/configuration directorythe layout, the entry routing table, and the cross-entry skill, agent, and output style
Project — <entry>/.claude/ ×5configuration directoryone per project entry: how to work inside that entry, and the instances only it uses
binds: principles, routesgoverning edgethe global instruction file's principles and "Filing" routes hold inside the workspace scope unchanged
assigns: the entry tablegoverning edgethe workspace CLAUDE.md names each project entry and when a request routes to it

Scope matrix

The scopes divide by how far a claim holds: the global scope carries what is true on any machine and in any repository, the workspace scope carries what coordinates the entries, and a project entry carries only its own working knowledge. Session composition

A session composes the scopes rather than choosing between them, loading the global instruction file, every ancestor CLAUDE.md down to its working directory, and the memory index of exactly one pool. A rule from any scope stays dormant until the session reads a file its paths key matches, which makes a rule the only configuration whose arrival depends on what the session opens. Subagents inherit the same composition, snapshotted at session start (global pool's setup-claude-subagents, verified 2026-07-16).

Router placement

Every scope declares its own predicate in the opening lines of its CLAUDE.md and the scope above assigns it, so no file decides its own home. The router for a thing lives one scope above the destinations it chooses between, which lets a reader who knows what a thing is find where it goes without opening any of the candidates.

RouterLives inRoutes
§Filing~/.claude/CLAUDE.mda durable takeaway, six ways

document placementthe same file and sectiona document no entry owns, to docs/ under an agent- or service- prefix

session placement~/workspace/.claude/skills/delegating/a delegated session, to a herdr pane and a repository

Each memory pool also restates its own boundary in its MEMORY.md header, so a reader already inside a pool never has to climb back to the router to check whether a file belongs there.

Two rows break the pattern the rest of this document follows, where a definition sits at global scope and its instances sit below. The rule format is defined in a setup-* memory rather than in a CLAUDE.md because it is a verified harness behavior rather than a preference, and the agent format is defined nowhere — only demonstrated, at the two scopes that hold instances.

gap The agent row has no definition to cite, so an author writing a new agent reverse-engineers the frontmatter from an existing file and nothing states which keys are required. The proposal agent-document-writing.html would move the document system's rules into the document-writer definition, but its Status reads Open, so nothing records whether the agent format stays by example or is written down beside the skill rule. The owner decides.

Omissions

The figures and tables claim placement and routing, and nothing else. Not shown, deliberately:

  • The contents of any configuration file — the matrix names files and the kinds they hold, never what they say. Read the file.
  • Settings and hooks — settings.json and settings.local.json exist at the global and workspace scopes and inside two entries, and ~/.claude/hooks/ holds the one authored hook, check-backlog-format.py. "Filing" names that hook as the enforcer of the backlog grammar, so it is machinery over the memory kind rather than a sixth kind of its own, and the harness owns where both live.
  • The rest of ~/.claude/ — the runtime directories beside the instruction files (sessions, plugins, caches, history) hold no authored configuration.
  • Transcript directories — ~/.claude/projects/ holds 11 directories but only 6 carry a memory/ pool. One without a pool, such as -Users-hyungmokim-workspace-kalaluthien-github-io, is a transcript store for sessions that ran there, and is not counted as a pool anywhere here.
  • Worktrees — ~/workspace/.claude-worktrees/ is empty, and camera/.claude/worktrees/ holds 13 directories that git worktree list in camera/ no longer reports. Neither is a project entry, and both are excluded from every count.
  • Load mechanics — the session panels name the condition that selects each source, not the order, the token budget, or what happens when two scopes disagree.
  • History — which scopes and entries existed before today. That log is the workspace pool's history-workspace-refactor.
