Answer

A kind of configuration lives in the scope whose reach matches how far its claim holds.

Conclusion
  1. 1 Global. What holds on any repository lives in ~/.claude/ — the principles, the filing routes, the two agent definitions.
  2. 2 Workspace. What coordinates the entries lives in ~/workspace/.claude/ — the entry table, the output style, the delegating skill.
  3. 3 Project. How to work inside one entry lives in that entry's own .claude/, and nothing there reaches a sibling.

Reach

Conclusion
  1. 1 Composition. A session composes the three scopes instead of choosing one; the working directory selects two of the four sources.
  2. 2 Dormancy. A rule waits until the session reads a file its paths key matches — never when it writes one.
  3. 3 Snapshot. Subagents inherit the composition as it stood at session start. Skills hot-reload; a new agent registers only on restart.

Routing

Conclusion
  1. 1 No self-placement. Each scope declares its predicate in its own CLAUDE.md, and a router elsewhere assigns it — no file decides its own home.
  2. 2 Router position. A router sits at the outermost scope of its candidate set, never below one of them, so a reader finds where a thing goes without opening any candidate.

Route 4 bars the global pool for the same reason route 3 owns it: there, a coordination procedure would hide behind a tool name that names only one of its parts.

Omissions

  • Two trees. The Commit field pins ~/workspace. The configuration itself lives in ~/.claude at a644f45, and its memory pools are in no repository.
  • File contents. The tables name files and kinds, never what a file says.
  • Harness machinery. Settings files, hooks, and plugin-supplied skills sit over the kinds, not in them; agent-hooks.html covers the hooks.
  • Other project directories. ~/.claude/projects/ holds 14 directories; 6 carry a memory/ pool, the rest hold session transcripts.
  • Load mechanics. Not the load order, the token budget, or what wins when two scopes disagree.
  • History. Which scopes and entries existed before; that log is the workspace pool's history-workspace-refactor.
