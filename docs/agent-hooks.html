Answer

Conclusion
  1. 1Prompt in. Every prompt in every project picks up one line from UserPromptSubmit — a plain-language writing reminder, the only hook here that shapes the reply instead of checking something.
  2. 2Tool call. PreToolUse on Bash rewrites the command through rtk to cut output tokens, and PostToolUse on Write|Edit fails a backlog write whose items break the pool contract's grammar.
  3. 3Git layer. A git commit inside that Bash call leaves the harness entirely: all six repositories run the same no-main-commits guard, and board alone also deploys on a version tag.
  4. 4Turn end. Stop blocks the first stop of each turn with the Filing reminder and lets the second through, so every turn gets exactly one pass over its own takeaways.

Layer ownership

Conclusion
  1. 1The trigger names the owner. A hook the session triggers — prompt, tool call, stop — is the harness's; a hook an index or a ref triggers is git's. No event fires both layers.
  2. 2One follows the operator, the other the clone. The four harness hooks sit in one file, ~/.claude/settings.json, and so apply in every repository this operator works; a git hook lives inside a clone, is never cloned, and fires for every actor — a peer agent, or the owner at a terminal — not only a Claude session.

Harness hooks

Conclusion
  1. 1Two guard the record, two guard the conduct. PostToolUse and Stop hold the memory pools' rules — the item grammar and the Filing pass; PreToolUse and UserPromptSubmit shape cost and register and refuse nothing.
  2. 2Stop is one-shot by construction. The jq filter emits its block only while stop_hook_active is false, so the reminder can never loop a turn.

Git hooks

Conclusion
  1. 1One guard, six repositories. Every clone runs the same file, ~/.claude/git-hooks/no-main-commits: it blocks a commit on main or master, passes a detached HEAD untouched, and prints the branch-or-worktree recipe.
  2. 2Three chain, three do not. Where a repository already owns a pre-commit hook, core.hooksPath points at .git/local-hooks, whose two-line hook runs the guard first and the repository's own hook second — any other value silently drops the guard.
  3. 3board also watches refs. reference-transaction is the only hook that sees a tag come into existence, and it starts one detached deploy per newly created vMAJOR.MINOR.PATCH tag.

  1. Entry — installed hook. The two-line pre-commit git actually executes, reached because core.hooksPath names its directory.
  2. Shared guard — machine-wide check. no-main-commits, run first so no chained hook can be ordered ahead of it; a non-zero exit here ends the commit.
  3. Repo hook — repository check. The hook that repository would have run anyway, exec'd last, so its exit status is the commit's.

The one hook outside this shape is board's reference-transaction: git has no post-tag hook, so it reads the committed transaction and starts one detached scripts/deploy-tag per new version tag, logging to ~/.local/state/board/release.log. A moved tag, a deleted tag, and every branch update are ignored.

Creation is the pair of ref values, not the old one alone — testing old by itself would redeploy on every git tag -d

git reports a tag move as old=<oid> new=<oid>, but a deletion as all zeros on both sides rather than the zero new value the name suggests (measured against git 2.51, 2026-08-04), so the hook requires both halves:

[[ $old =~ ^0+$ && ! $new =~ ^0+$ ]] || continue

Omissions

The figures and tables claim which hooks are installed, who owns each, and what each refuses; nothing else. Not shown, deliberately:

  • The pin's reach — the Commit field pins ~/workspace, which holds no hook source: the harness hooks and the shared guard are tracked in ~/.claude at a1eda25, and the per-repository wiring under .git/ is version-controlled nowhere.
  • Inside the chained hooks — the last column of the repository table names what each adds in one line; the checks themselves belong to those repositories' own documents.
  • The rtk rewrite — which commands rtk proxies, and by how much it trims them, is the tool's own fact (~/.claude/RTK.md), not this view's.
  • Other hook kinds — the walk covered .git/hooks/ and .git/local-hooks/ in the six repositories on 2026-08-04, samples excluded; no other hook file was installed. Server-side hooks and CI checks are a different layer again.
  • Ordering across layers — the figure shows that a Bash call crosses into git, not how a harness hook and a git hook would interleave if both had something to say.
